# 架构

Moli Todo 是一个待办清单：一个服务端保存数据，网页和桌面客户端都是它的使用者。本文只写模块划分、数据流和重要决定的原因；规则本身在 MoliSpec 的规范里。

## 模块

| 目录       | 是什么                                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| `server/`  | Fastify（TypeScript、Zod），SQLite（Drizzle）。负责登录、`/api/v1` 接口、`/healthz`，并提供网页的静态文件 |
| `web/`     | Vite + React + Tailwind 4。网页版界面，桌面端复用同一套组件                                               |
| `shared/`  | 服务端和前端共用的 Zod 结构和逻辑（接口的请求和响应形状，之后加同步引擎）                                 |
| `desktop/` | Tauri 2 桌面端（Windows、macOS arm64）。后续加入                                                          |

整个仓库是**一个 npm 包**（一份 `package.json`、一份锁文件），不分多个子包。原因：服务端、网页、桌面共享类型，分包要再配构建顺序和发布，对一个人维护的应用没有收益。服务端用 esbuild 打成 `dist/server/`，依赖留在 `node_modules`。

## 登录

- **网页**：服务端自己做 OIDC（规范 008 的 8.5）。`/auth/login` 只做跳转，到 Authelia 登录后回到 `/auth/callback`，服务端验证 ID Token，发自己的会话 cookie（`__Host-todo_session`）。会话只存用户标识，不存 Authelia 的令牌。未登录访问页面直接跳到 Authelia，接口回 401 JSON。
- **桌面**：公开客户端 `moli-todo-app`，设备码登录。桌面端把 ID Token 放在 `Authorization: Bearer` 里，服务端用 Authelia 的验证密钥在本地验签，`aud` 必须是桌面客户端。
- 一个请求只认一种凭据：带了 Bearer 就只看令牌，忽略 cookie；没带才看 cookie。cookie 会话的写操作还要核对 `Origin`（规范 008 的 8.5.7、8.7.4）。
- 用户的唯一键是 `preferred_username` 转小写，写在每条数据的 `owner` 上。
- **为什么桌面端的令牌不做"5 分钟内签发"的限制**：网页回调时 ID Token 刚签发，所以限制 5 分钟防重放；桌面端的令牌要用到过期，由客户端用刷新令牌更新，只检查签名、`iss`、`aud`、`exp` 和"不是未来签发的"。

## 数据库与升级

SQLite 文件在数据卷里，迁移文件由 `npm run db:generate` 生成，部署时先备份再用同一个镜像跑 `node dist/server/migrate.js`。

**旧版客户端会不会被数据库改动弄坏？不会，因为客户端从不直接碰数据库，只认接口。** 做法：

1. 数据库结构随时可以迁移，只要对外的接口不变；迁移只加不删（规范 009 的 9.8）。
2. 接口只加不改：可以加字段，旧客户端忽略不认识的字段。
3. 必须不兼容时，开新路径 `/api/v2`，`/api/v1` 保留到旧版本退役。
4. 兜底：客户端每次请求带版本，服务器配置"最低支持版本"，低于它回 `426` 和 JSON 说明；客户端提示"请更新"，本机数据照常可看可改（排队，更新后再同步），不清除数据。

## 技术选型和原因

| 决定                                                                     | 原因                                                                                                         |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Fastify                                                                  | 用户指定；成熟、插件多、与 Zod 配合简单                                                                      |
| SQLite + Drizzle                                                         | 规范默认；一个人用，一个文件最简单                                                                           |
| 会话存在 SQLite，不放内存                                                | 重启和部署不会让所有人掉线                                                                                   |
| 登录尝试（state、nonce、PKCE）存在服务端，另加一个短期 cookie 绑定浏览器 | 规范 8.5.2 要求；绑定 cookie 防止别人发起的登录链接在你的浏览器上完成                                        |
| `jose` 验令牌，不用整套 OIDC 库                                          | 只需要验签和校验声明，依赖越少越好（规范 010 的 10.4.4）                                                     |
| 钥匙集缓存，遇到未知钥匙最多每分钟刷新一次                               | 规范 8.5.3 要求遇未知钥匙刷新；加频率限制，防止有人拿伪造的钥匙编号让服务器反复请求 Authelia                 |
| 旧 Electron 版不兼容、不迁移，另用新名字安装                             | 用户决定；只提供"导入旧任务"，见后续的同步和导入设计                                                         |
| 桌面端用 Tauri                                                           | 规范 10.2：Electron 应用重写时改用 Tauri，且要支持 macOS                                                     |
| 桌面窗口不再用透明边框，不做鼠标穿透                                     | 旧版为了自绘圆角和阴影，窗口比浮窗大一圈透明边，才需要鼠标穿透；新版用系统自带的圆角和阴影，窗口就是浮窗本身 |
