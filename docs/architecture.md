# 架构

Moli Todo 是一个待办清单：一个服务端保存数据，网页和桌面客户端都是它的使用者。本文只写模块划分、数据流和重要决定的原因；规则本身在 MoliSpec 的规范里。

## 模块

| 目录       | 是什么                                                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| `server/`  | Fastify（TypeScript、Zod），SQLite（Drizzle）。负责登录、`/api/v1` 接口、`/healthz`，并提供网页的静态文件              |
| `web/`     | Vite + React + Tailwind 4。网页版界面，桌面端复用同一套组件                                                            |
| `shared/`  | 服务端和前端共用的 Zod 结构和逻辑：接口形状、同步引擎、排序键、新加坡时间和耗时的换算、旧任务导入                      |
| `desktop/` | Tauri 2 桌面端（Windows、macOS arm64）：`src-tauri/`（Rust 外壳）、`core/`（本机文件的 Rust 库）、`src/`（界面和逻辑） |

整个仓库是**一个 npm 包**（一份 `package.json`、一份锁文件），不分多个子包。原因：服务端、网页、桌面共享类型，分包要再配构建顺序和发布，对一个人维护的应用没有收益。服务端用 esbuild 打成 `dist/server/`，依赖留在 `node_modules`。

## 登录

- **网页**：服务端自己做 OIDC（规范 008 的 8.5）。`/auth/login` 只做跳转，到 Authelia 登录后回到 `/auth/callback`，服务端验证 ID Token，发自己的会话 cookie（`__Host-todo_session`）。会话只存用户标识，不存 Authelia 的令牌。未登录访问页面直接跳到 Authelia，接口回 401 JSON。
- **桌面**：公开客户端 `moli-todo-app`，设备码登录。桌面端把 ID Token 放在 `Authorization: Bearer` 里，服务端用 Authelia 的验证密钥在本地验签，`aud` 必须是桌面客户端。
- 一个请求只认一种凭据：带了 Bearer 就只看令牌，忽略 cookie；没带才看 cookie。cookie 会话的写操作还要核对 `Origin`（规范 008 的 8.5.7、8.7.4）。
- 用户的唯一键是 `preferred_username` 转小写，写在每条数据的 `owner` 上。
- **为什么桌面端的令牌不做"5 分钟内签发"的限制**：网页回调时 ID Token 刚签发，所以限制 5 分钟防重放；桌面端的令牌要用到过期，由客户端用刷新令牌更新，只检查签名、`iss`、`aud`、`exp` 和"不是未来签发的"。

## 同步

规范 009 的 9.7，离线优先、一条任务一项。

- **一条任务**：`id`（客户端生成）、`text`、`done`、`doneAt`、`archived`、`duration`（分钟）、`position`（排序键）、`deleted`（删除标记）、`version`（服务器每次修改加一）。服务器另记每条任务的变更序号 `seq`，只用来做拉取游标，不对外暴露任务上的这个字段。
- **接口**（`/api/v1`，所有请求带 `X-Moli-Client: <客户端>/<版本>`）：
  - `GET /tasks/changes?cursor=&limit=`：游标之后的变化（含删除标记），返回新游标和 `hasMore`，客户端翻页直到 `hasMore` 为假。
  - `PUT /tasks/:id`，带 `baseVersion`（新建为 0）：基于当前版本就接受，返回 200 和新值；版本对不上返回 409 和服务器当前的值。同样的内容重发（上次的回应丢了）不算冲突。
- **冲突**：以服务器为准。客户端把被拒绝的那份内容放进"冲突"列表，界面提示"已采用服务器上的版本"，可复制回来后忽略（9.7.4）。删除用标记，不真删，所以别的设备不会把删掉的任务带回来；删除之后又有人基于旧版本改它，也是删除赢，改的内容留在冲突列表里。
- **客户端的同步引擎**（`shared/sync.ts`）：保存"服务器上最后的样子"、"还没发出去的修改"和"拉取游标"，界面看到的是后者叠在前者上。每次先发送、再拉取。断网和 5xx 当离线，修改留着重试；401/403 是登录失效，426 是版本太旧，这两种都不清本机数据。网页版把这份副本放内存，改了立刻同步，不做离线队列；桌面版把它存进本机文件。
- **排序**：`position` 是 base-62 的分数键，拖动一条只改这一条，别的任务不动（`shared/position.ts`）。
- **时间**：已完成视图按新加坡时间分天（规范 013），固定加 8 小时换算，各设备结果一致。

## 导入哞哞清单的历史任务

在设置里选旧版的 `store.json`。**只加不改**：

- 每条旧任务的新 id 由旧 id 算出（固定的哈希），所以同一份文件在哪台设备导入，得到的都是同样的 id。
- 导入时新 id 已存在（包括被改过、被删掉的）就跳过，从不覆盖、不修改、不复活；未完成的接在列表末尾，已完成的按旧完成时间进已完成视图。
- 再导入一次：全部跳过，只加旧文件里新增的；提示"导入 N 条，跳过 M 条（之前导入过）"。如果另一台设备已经导入过、本机还没同步到，发送时服务器回 409，这种"只加"的任务静默丢弃，不弹冲突。

## 桌面端

- **分工**：Rust 只做前端做不到的事——读写本机数据文件、单实例、退出、插件注册（开机自启、网络请求、打开浏览器）。登录、同步、窗口位置、托盘菜单都写在 TypeScript 里（`desktop/src/`），藏在 `Platform` 和 `WindowControl` 两个接口后面，所以逻辑能在 jsdom 里测；只有和 Tauri 直接对接的 `tauri.ts` 不进覆盖率。界面复用 `web/` 的组件（`TodoBody`、`Settings`）。
- **登录**：设备码（规范 008 的 8.7）。点“登录”后向 Authelia 要验证码，用系统浏览器打开登录页，用户批准后拿到令牌。刷新令牌存本机 `settings.json`（不进系统钥匙串），ID Token 只在内存里，距离过期不到 1 分钟就用刷新令牌换新。只有服务器明确回 401 才回到“未登录”，本机任务不清；退出登录时会问是否同时删除本机任务。
- **本机文件**（应用数据目录，Rust 只允许这两个名字，写入先写临时文件再改名）：`state.json`（任务副本、待提交队列、游标、所属账号）和 `settings.json`（刷新令牌、窗口位置和大小、折叠、永久置顶）。文件损坏时改名留存（`*.corrupt-<时间>`），再从空白开始，不静默覆盖。
- **同步时机**：启动、窗口回到前台、网络恢复、每 15 分钟、改动后 300 毫秒（仅在空闲时）。登录的账号变了，先清掉上一个账号的副本，不混用。
- **窗口**：无边框，用系统的圆角和阴影，窗口就是浮窗本身。位置保存后，启动时夹回可见区域（拔过显示器也不会跑到屏幕外）；关窗只隐藏，托盘里“退出”才真退出。
- **已知限制**：托盘图标暂用应用图标，不是 macOS 的模板图标（设计库里还没有）；自动更新放到发布流程里做；窗口拖动、高分屏位置、托盘这些只能在真机上验证。
- **构建**：这台开发机没有 webkit，Tauri 外壳在 CI 的 Windows 和 macOS 运行器上编译（`build` 作业的矩阵）；Rust 核心库在三个系统上都跑测试。

## 旧客户端和最低版本

服务器可配 `MIN_CLIENT_VERSION`（`X.Y.Z`，不配就不限制）。请求头里的版本低于它，`/api/` 下的请求回 `426`，JSON 带 `error.code = upgrade_required` 和 `minVersion`。没带版本头的请求（网页，总是最新）和格式不认识的头不拦。

## 数据库与升级

SQLite 文件在数据卷里，迁移文件由 `npm run db:generate` 生成，部署时先备份再用同一个镜像跑 `node dist/server/migrate.js`。

**旧版客户端会不会被数据库改动弄坏？不会，因为客户端从不直接碰数据库，只认接口。** 做法：

1. 数据库结构随时可以迁移，只要对外的接口不变；迁移只加不删（规范 009 的 9.8）。
2. 接口只加不改：可以加字段，旧客户端忽略不认识的字段。
3. 必须不兼容时，开新路径 `/api/v2`，`/api/v1` 保留到旧版本退役。
4. 兜底：客户端每次请求带版本，服务器配置"最低支持版本"，低于它回 `426` 和 JSON 说明；客户端提示"请更新"，本机数据照常可看可改（排队，更新后再同步），不清除数据。

## 技术选型和原因

| 决定                                                                     | 原因                                                                                                         |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Fastify                                                                  | 用户指定；成熟、插件多、与 Zod 配合简单                                                                      |
| SQLite + Drizzle                                                         | 规范默认；一个人用，一个文件最简单                                                                           |
| 会话存在 SQLite，不放内存                                                | 重启和部署不会让所有人掉线                                                                                   |
| 登录尝试（state、nonce、PKCE）存在服务端，另加一个短期 cookie 绑定浏览器 | 规范 8.5.2 要求；绑定 cookie 防止别人发起的登录链接在你的浏览器上完成                                        |
| `jose` 验令牌，不用整套 OIDC 库                                          | 只需要验签和校验声明，依赖越少越好（规范 010 的 10.4.4）                                                     |
| 钥匙集缓存，遇到未知钥匙最多每分钟刷新一次                               | 规范 8.5.3 要求遇未知钥匙刷新；加频率限制，防止有人拿伪造的钥匙编号让服务器反复请求 Authelia                 |
| 旧 Electron 版不兼容、不迁移，另用新名字安装                             | 用户决定；只提供"导入旧任务"，见后续的同步和导入设计                                                         |
| 桌面端用 Tauri                                                           | 规范 10.2：Electron 应用重写时改用 Tauri，且要支持 macOS                                                     |
| 桌面窗口不再用透明边框，不做鼠标穿透                                     | 旧版为了自绘圆角和阴影，窗口比浮窗大一圈透明边，才需要鼠标穿透；新版用系统自带的圆角和阴影，窗口就是浮窗本身 |
