# 架构

Moli Todo 是一个待办清单：一个服务端保存数据，网页是它的使用者。本文只写模块划分、数据流和重要决定的原因；规则本身在 MoliSpec 的规范里。

## 模块

| 目录      | 是什么                                                                                                                                      |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `server/` | Fastify（TypeScript、Zod），SQLite（Drizzle）。负责登录、`/api/v2` 同步接口、`/healthz`，并提供网页的静态文件                               |
| `web/`    | Vite + React + Tailwind 4。网页版界面；`web/src/lib/` 放同步引擎、HTTP 传输、排序键、新加坡时间换算、数据读写、本子和翻页几何、图表、主题色 |
| `shared/` | 服务端和网页都要用的 Zod 结构：接口形状（`api.ts`）、各类记录和同步接口（`records.ts`）、`#标签` 解析（`tags.ts`）                          |

整个仓库是**一个 npm 包**（一份 `package.json`、一份锁文件），不分多个子包。原因：服务端和网页共享类型，分包要再配构建顺序和发布，对一个人维护的应用没有收益。服务端用 esbuild 打成 `dist/server/`，依赖留在 `node_modules`。

## 页面

底部（电脑上是左侧）五个入口：

- **今天**：当天的清单，像记事本一样连续输入。行首两个空格缩进（只是视觉缩进，不是子任务），`#词` 是标签，已完成的行尾手填用时，页底是当天用时之和。昨天没做完的，顶部提示，手动挑哪些挪到今天（只管昨天）。
- **索引**：搜索所有任务；标签列表（条数、用时）；标签详情按天分组，可改名（同时改所有任务里的文字）、改颜色。缩进在某条带标签的任务下面的行，也算进那个标签。
- **本子**：每年一本，只有写过东西的天才有一页，页码连续。合上时是封面（内置公版名画或自己上传），点开有 3D 翻开封面的动画；拖页角卷页翻页，手机单页、电脑两页对开。只读，点页面跳到「今天」的那一天去改。
- **计时**：只有正计时，可以从今天的任务里取名字；统计页有累计、日均、饼图（日/周/月/自定义）、月度和年度曲线。
- **我的**：主题色（选或输入色号，只改强调色）、浅色/深色/跟随系统、本子封面、没能同步的改动。

## 登录

- **网页**：服务端自己做 OIDC（规范 008 的 8.5）。`/auth/login` 只做跳转，到 Authelia 登录后回到 `/auth/callback`，服务端验证 ID Token，发自己的会话 cookie（`__Host-todo_session`）。会话只存用户标识，不存 Authelia 的令牌。未登录访问页面直接跳到 Authelia，接口回 401 JSON。
- 接口只认会话 cookie，`Authorization` 请求头一律忽略（不是登录方式）。cookie 会话的写操作还要核对 `Origin`（规范 008 的 8.5.7）。
- 用户的唯一键是 `preferred_username` 转小写，写在每条数据的 `owner` 上。

## 同步

规范 009 的 9.7，服务器为准，网页改了立刻发。

- **记录**：所有数据都是"记录"，一种同步方式。每条记录有 `kind`、`id`（客户端生成）、`data`（按种类用 Zod 校验）、`deleted`（删除标记）、`version`（服务器每次修改加一）。服务器另记每个用户的变更序号 `seq`，只用来做拉取游标。种类：
  - `task`：哪天（`day`）、文字（含 `#标签`）、缩进、是否完成、完成时间、用时（分钟，手填）、高亮颜色、排序键。
  - `tag`：id 是标签名小写；名字和颜色（没有记录的标签用主题色）。
  - `session`：一次正计时，名字、起止时间、秒数（不含暂停）、哪天。
  - `timer`（只有一条 `current`）：正在用的计时器，存在服务器上，刷新或换设备接着走。
  - `settings`（只有一条）：主题色、浅色/深色/跟随系统、选的封面。
  - `cover`（只有一条）：上传的封面图，浏览器先缩小压缩成 data URL（CSP 只允许 `img-src 'self' data:`），和设置分开，改主题色不用重发图片。
- **接口**（`/api/v2`，所有请求带 `X-Moli-Client: <客户端>/<版本>`）：
  - `GET /changes?cursor=&limit=`：游标之后的变化（含删除标记），返回新游标和 `hasMore`，客户端翻页直到 `hasMore` 为假。
  - `PUT /records/:kind/:id`，带 `baseVersion`（新建为 0）：基于当前版本就接受，返回 200 和新值；版本对不上返回 409 和服务器当前的值。同样的内容重发（上次的回应丢了）不算冲突。
  - 2.x 的 `/api/v1/tasks/*` 一律回 426，让部署前就开着的旧网页自动刷新；`/api/v1/me` 保留。
- **冲突**：以服务器为准。客户端把被拒绝的那份内容放进"冲突"列表，「我的」页提示，可忽略（9.7.4）。删除用标记，不真删，所以别的设备不会把删掉的记录带回来。
- **客户端的同步引擎**（`web/src/lib/sync.ts`）：保存"服务器上最后的样子"、"还没发出去的修改"和"拉取游标"，界面看到的是后者叠在前者上。每次先发送、再拉取。断网和 5xx 当离线，修改留着重试；401/403 是登录失效，426 是版本太旧，这两种都不清本机数据。网页版把这份副本放内存，改了立刻同步，不做离线队列。
- **排序**：`position` 是 base-62 的分数键，拖动一条只改这一条，别的任务不动（`web/src/lib/position.ts`）。
- **时间**：按新加坡时间分天（规范 013），固定加 8 小时换算，各设备结果一致。

## 翻页

本子的翻页不用库，几何在 `web/src/lib/page-curl.ts`（纯函数，有单测）：折线是页角和手指连线的中垂线，被翻起的部分用多边形裁切，背面用一个镜像矩阵放到折线另一侧。`web/src/lib/book.ts` 管哪几页摆在哪、翻到哪；`web/src/components/BookStage.tsx` 只负责把这些画出来（CSS `clip-path` 加 `matrix()`）和处理手势：拖、甩、点左右边缘、键盘、滚轮、鼠标停在页角时页角微微翘起。系统设了"减少动画"时改成淡入淡出。

## 旧客户端和最低版本

服务器可配 `MIN_CLIENT_VERSION`（`X.Y.Z`，不配就不限制）。请求头里的版本低于它，`/api/` 下的请求回 `426`，JSON 带 `error.code = upgrade_required` 和 `minVersion`。没带版本头的请求和格式不认识的头不拦。

网页的请求都带版本头（`todo-web/<版本>`），所以部署前就打开着的旧网页会收到 426，这时自动刷新一次，拿到最新的网页。为了防止服务器配错时无限刷新，5 分钟内只自动刷新一次，其间角落显示「版本太旧，请刷新页面」。

## 数据库与升级

SQLite 文件在数据卷里，迁移文件由 `npm run db:generate` 生成，部署时先备份再用同一个镜像跑 `node dist/server/migrate.js`。

**旧版客户端会不会被数据库改动弄坏？不会，因为客户端从不直接碰数据库，只认接口。** 做法：

1. 数据库结构随时可以迁移，只要对外的接口不变；迁移只加不删（规范 009 的 9.8）。
   - 例外：3.0 重写时用户明确同意删库重建，迁移 `0003` 删掉了 2.x 的 `tasks` 表，任务数据不保留。旧迁移文件都还在，生产库的迁移记录能按顺序接上。
2. 接口只加不改：可以加字段，旧客户端忽略不认识的字段。
3. 必须不兼容时，开新路径 `/api/v2`，`/api/v1` 保留到旧版本退役。
4. 兜底：客户端每次请求带版本，服务器配置"最低支持版本"，低于它回 `426` 和 JSON 说明；网页收到后自动刷新。

## 技术选型和原因

| 决定                                                                     | 原因                                                                                         |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| Fastify                                                                  | 用户指定；成熟、插件多、与 Zod 配合简单                                                      |
| SQLite + Drizzle                                                         | 规范默认；一个人用，一个文件最简单                                                           |
| 会话存在 SQLite，不放内存                                                | 重启和部署不会让所有人掉线                                                                   |
| 登录尝试（state、nonce、PKCE）存在服务端，另加一个短期 cookie 绑定浏览器 | 规范 8.5.2 要求；绑定 cookie 防止别人发起的登录链接在你的浏览器上完成                        |
| `jose` 验令牌，不用整套 OIDC 库                                          | 只需要验签和校验声明，依赖越少越好（规范 010 的 10.4.4）                                     |
| 钥匙集缓存，遇到未知钥匙最多每分钟刷新一次                               | 规范 8.5.3 要求遇未知钥匙刷新；加频率限制，防止有人拿伪造的钥匙编号让服务器反复请求 Authelia |
| 旧 Electron 版不兼容、不迁移                                             | 用户决定                                                                                     |
| 3.0 删库重建，不迁移 2.x 的任务                                          | 用户决定；数据结构从"只有任务"改成通用记录                                                   |
| 翻页、图表自己画，不引库                                                 | 要的效果库做不到（卷页而不是整页硬翻），图表只有饼图和曲线两种，依赖越少越好                 |
